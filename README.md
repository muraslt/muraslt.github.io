# Мурад Султанов: сайт-визитка

Статичный одностраничный сайт: HTML, CSS и немного JS. Без сборки, без внешних подключений, без трекеров. Открывается двойным кликом по `index.html` и работает без сервера.

Все пути относительные, поэтому папку можно скопировать в любой репозиторий или на любой хостинг без правок.

## Что где лежит

| Файл или папка | Что это |
|---|---|
| `index.html` | Страница целиком (тексты, мета-теги, CSP) |
| `assets/style.css` | Все стили. Цвета и радиус заданы переменными в начале файла |
| `assets/main.js` | Появление блоков, липкая кнопка на телефоне, лёгкий параллакс. Без JS сайт читается полностью |
| `assets/fonts/` | Шрифт Forum (woff2, кириллица и латиница), хостится у себя |
| `assets/img/` | Портрет: AVIF, WebP, JPEG в размерах 800/1400/2000 (десктоп) и 640/960/1240 (телефон) |
| `assets/portrait-original.jpg` | Исходное фото без изменений |
| `assets/grain.png` | Лёгкое зерно, только на фоне страницы |
| `og-image.jpg` | Превью для Telegram, Instagram и мессенджеров, 1200×630 |
| `favicon.svg`, `favicon-32.png`, `apple-touch-icon.png` | Монограмма «М» |
| `robots.txt`, `sitemap.xml` | С плейсхолдером `ДОМЕН` (см. ниже) |
| `.nojekyll` | Нужен GitHub Pages, чтобы он не пытался обрабатывать файлы |
| `qa/` | Скриншоты проверки на 390 и 1440 и отчёт `REPORT.md` |

## Временная публикация на GitHub Pages

Предполагается, что папка скопирована в отдельный публичный репозиторий.

1. Скопируйте содержимое папки `murad/` в корень нового репозитория (чтобы `index.html` лежал в корне).
2. В репозитории: **Settings → Pages → Build and deployment → Source: Deploy from a branch → Branch: `main`, folder: `/ (root)` → Save**.
3. Через 1-2 минуты сайт будет доступен по адресу `https://<ваш-аккаунт>.github.io/<имя-репозитория>/`.

Пока сайт на временном адресе, он **закрыт от индексации** строкой `<meta name="robots" content="noindex, nofollow">` в `index.html`. Как её убрать: см. «Переезд на свой домен».

## Перенос на другой хостинг

Сайт это просто набор файлов.

- **Beget:** загрузите содержимое папки в каталог `public_html` нужного сайта (по FTP или через файловый менеджер панели).
- **Cloudflare Pages:** Workers & Pages → Create → Pages → Upload assets (или подключите репозиторий). Build command пустая, output directory `/`.
- Пути относительные, поэтому ничего менять в коде при переезде не нужно.

## Переезд на свой домен

1. **Привяжите домен.**
   - Для GitHub Pages: в корне репозитория создайте файл `CNAME` с одной строкой, вашим доменом (например `example.ru`), либо укажите домен в Settings → Pages → Custom domain.
   - У регистратора добавьте DNS-записи. Для корневого домена: четыре записи **A** на `185.199.108.153`, `185.199.109.153`, `185.199.110.153`, `185.199.111.153` (при желании ещё записи **AAAA** `2606:50c0:8000::153`, `2606:50c0:8001::153`, `2606:50c0:8002::153`, `2606:50c0:8003::153`). Для `www`: запись **CNAME** на `<ваш-аккаунт>.github.io`.
   - После проверки домена включите **Enforce HTTPS** в Settings → Pages.
   - Для Beget и Cloudflare записи подскажет их панель: обычно достаточно сменить NS-серверы или добавить одну A-запись.
2. **Замените плейсхолдер `ДОМЕН`** на настоящий адрес (поиск по слову `ДОМЕН` в папке):
   - `index.html`: `<link rel="canonical">`, `og:url`, `og:image`, `twitter:image` (картинка должна быть по абсолютному адресу вида `https://example.ru/og-image.jpg`, иначе превью в Telegram и Instagram не покажется);
   - `sitemap.xml`: адрес в `<loc>`;
   - `robots.txt`: раскомментируйте строку `Sitemap:` и подставьте адрес.
3. **Снимите запрет индексации:** удалите из `index.html` строку `<meta name="robots" content="noindex, nofollow">` и комментарий над ней. Без этого поисковики не будут показывать сайт.
4. Telegram и Instagram кэшируют превью ссылок. После смены адреса или картинки обновите превью через бота `@WebpageBot` в Telegram.

## Заголовки безопасности и кэш

GitHub Pages не даёт задавать собственные HTTP-заголовки, поэтому `Content-Security-Policy` и `referrer` заданы через `<meta>` в `index.html` (заголовки вроде `X-Frame-Options`, `frame-ancestors` и `Strict-Transport-Security` через meta не работают). На хостинге, где заголовки настраиваются (Beget через `.htaccess`, Cloudflare Pages через файл `_headers` или Transform Rules, Nginx), добавьте: `Content-Security-Policy` с теми же значениями плюс `frame-ancestors 'none'`, `X-Content-Type-Options: nosniff`, `Strict-Transport-Security: max-age=31536000`, `Referrer-Policy: no-referrer`, и долгий кэш для `assets/` и `og-image.jpg` (`Cache-Control: public, max-age=31536000, immutable`; при замене файлов меняйте их имена) и короткий для `index.html`. Файлы `netlify.toml` и `_headers` в проект намеренно не добавлялись.

## Как добавить отзывы позже

В `index.html` перед блоком «Контакты» есть закомментированная заготовка `Отзывы`. Раскомментируйте её и вставляйте только настоящие отзывы с письменного согласия автора. Стили для блока (`.reviews`) нужно будет дописать в `assets/style.css` по образцу остальных секций: заголовок `h2`, текст отзыва шрифтом Forum, подпись приглушённым цветом. Так же устроена заготовка «В деле» под второе фото: положите файл в `assets/img/` и раскомментируйте блок.

## Как добавить Яндекс.Метрику позже

Сейчас на сайте нет ни аналитики, ни cookie-баннера. Чтобы добавить Метрику:

1. Создайте счётчик на metrika.yandex.ru и возьмите код (лучше без Вебвизора, он и требует согласия на cookie).
2. Вынесите код счётчика в файл `assets/metrika.js` и подключите его в `index.html`: `<script src="assets/metrika.js" defer></script>`. Встроенный (inline) скрипт не заработает из-за CSP.
3. Обновите CSP в `index.html`: добавьте `https://mc.yandex.ru` в `script-src`, `img-src` и `connect-src`, а `https://mc.yandex.ru` и `https://yastatic.net` в `script-src` при необходимости (точный список даёт документация Яндекса).
4. Добавьте на сайт уведомление об обработке данных, как требует закон (для этого появится блок текста и ссылка на политику). Это нарушает правило «никакого cookie-баннера», поэтому решайте осознанно.
5. Цели: клик по кнопкам с атрибутом `data-cta` (`hero`, `final`, `sticky`) удобно отслеживать этим атрибутом.
